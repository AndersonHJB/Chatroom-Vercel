# Vercel 临时聊天室 · 静默启动 + WebRTC P2P 文件传输

这是一个可以直接部署到 Vercel 的临时聊天室，不使用 Redis、不使用数据库，也不把文件上传到 Vercel。

## 核心设计

### 1. 默认完全静默

页面初次打开时：

- 不请求 `/api/chat`
- 不检查管理员在线状态
- 不轮询
- 不发送管理员心跳
- 不注册在线 peer
- 不交换 WebRTC 信令
- 不创建 `RTCPeerConnection`
- 不启动本地 15 秒清理定时器

只有两种操作会让聊天室开始访问 API：

1. 管理员点击“管理员上线”，输入正确的 `ADMIN_PASSWORD`；
2. 访客主动点击“进入聊天室”，只检查一次管理员是否在线。

如果管理员没有在线，访客检查结束后继续保持静默，不会自动重试。

> 注意：网站本身部署在 Vercel 时，用户首次访问 HTML/CSS/JS 静态文件仍然属于 Vercel 静态资源请求。“静默”指页面加载完成后的聊天室业务逻辑不产生后台 API / Function 请求。

### 2. 管理员上线即启动聊天室

管理员密码验证成功后：

- 标记管理员在线；
- 开始聊天同步；
- 开始在线 peer 列表同步；
- 必要时交换 WebRTC SDP 信令；
- 允许文字聊天与 P2P 文件发送。

管理员点击“退出管理员”后：

- 服务端立即标记离线；
- 本地停止轮询；
- 停止本地维护定时器；
- 关闭全部 WebRTC 连接；
- 清空当前 Function 实例的 peer / signal 临时状态。

若管理员直接关掉页面，没有点退出，服务端在线状态会在短 TTL 后自动失效。

### 3. 任意文件 P2P 直传

文件 `<input>` 没有 `accept` 类型限制，浏览器提供的任意 `File` 都按二进制发送，例如：

- 图片：JPG / PNG / GIF / WebP / HEIC ...
- 视频：MP4 / MOV / MKV ...
- 压缩包：ZIP / RAR / 7z / tar.gz ...
- 安装包：DMG / PKG / EXE / MSI / APK ...
- PDF、Word、PPT、代码、模型文件及其他任意文件。

文件本体通过 WebRTC `RTCDataChannel` 浏览器到浏览器传输，不经过 `/api/chat`，不会进入聊天 JSON，也不会写入 `localStorage`。

### 4. 支持选择、粘贴、拖拽

文件进入“待发送队列”的方式：

- 点击“选择文件”；
- 从 Finder / Windows 资源管理器复制文件，然后在页面按 `⌘V` / `Ctrl+V`；
- 截图后直接粘贴；
- 把文件拖入粘贴区域。

这些操作只修改当前浏览器内存中的文件队列，不会立即上传或发送。

随后：

1. 选择接收者；
2. 可以逐个移除文件；
3. 点击“发送文件”；
4. 才开始 WebRTC 建连和 P2P 传输。

剪贴板是否能提供某种文件由浏览器和操作系统决定。只要 `clipboardData.files` 中能够拿到 `File`，本项目不检查扩展名和 MIME 类型，会直接按任意二进制文件处理。

## 聊天记录

- 普通访客文字消息：30 分钟 TTL；
- 管理员文字消息：当前版本不过期；
- 浏览器使用 `localStorage` 缓存文字记录；
- 管理员支持 JSON 导入 / 导出；
- P2P 文件永远不写入 JSON；
- 管理员支持清空当前服务器内存中的聊天记录。

## 重要限制

本项目按照要求没有使用 Redis、数据库或其他共享存储。Vercel Function 内存不是可靠的跨实例共享状态：

- 冷启动可能丢失服务器内存状态；
- 多实例扩容时不同实例可能看到不同的临时状态；
- 重新部署会清空服务器内存；
- 因此适合轻量、临时、小规模聊天室，不适合作为可靠的长期聊天系统。

WebRTC 默认只配置 STUN，不配置 TURN，因此文件不会在 P2P 失败时退化成服务器中继。某些严格 NAT、公司网络或防火墙环境可能无法直连。

接收端当前会把收到的文件块暂存在浏览器内存，完成后生成 Blob，因此超大文件会受到浏览器可用内存限制。

## Vercel 部署

将目录推送到 GitHub，然后在 Vercel Import 项目即可。

在 Vercel 项目中添加环境变量：

```text
ADMIN_PASSWORD=你的管理员密码
```

然后重新部署。

无需 npm install，没有第三方运行时依赖。

## 静默状态下的 30 分钟删除机制

- 浏览器始终保留一个 15 秒本地定时器，只检查 `localStorage` 中消息的 `expiresAt` 并删除过期访客消息。
- 该定时器不包含 `fetch`，不会请求 `/api/chat`，因此不会消耗 Vercel API / Function / 网络流量。
- Vercel Function 内存中的过期消息不通过后台定时任务清理；聊天室静默时服务器完全不执行。下次 API 被主动调用时，`cleanupState()` 会先删除所有过期消息再返回。
